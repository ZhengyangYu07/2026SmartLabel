# SmartLabel 主题分类主动学习流程说明

本文档是 SmartLabel 在 TorchSSL-main 目录中的集成说明，目标不是复述原始 TorchSSL 仓库介绍，而是把平台里的文本和主题分类流程整理成一套可落地的主动学习闭环。

## 1. 设计目标

这个系统的核心不是单次分类准确率，而是“少量人工标注 + 主动学习 + 自动接收高置信度预测”的闭环。

目标包括：

1. 冷启动时只需要很少的人工标注样本即可启动模型。
2. 优先把不确定性高的样本交给用户标注。
3. 支持用户一键通过高置信度预测标签，减少重复劳动。
4. 要求每个类别至少有一个人工标注样本，避免类别完全缺失时被模型盲猜。

## 2. 系统流程

### 2.1 冷启动

1. 用户创建任务后，先为每个目标类别提供至少 1 个人工标注样本。
2. 如果某个类别还没有任何人工标签，则不允许它进入自动接收流程。
3. 这一阶段的目标是让模型至少知道“有哪些类别存在”。

### 2.2 数据准备

1. 平台将有标签样本和无标签样本合并成统一数据集。
2. 文本数据统一转成包含 `text`、`label`、`is_labeled` 三列的结构。
3. `is_labeled=True` 表示人工标注样本，`is_labeled=False` 表示待预测样本。

### 2.3 模型训练与预测

1. 系统先训练基础文本分类器，生成每个样本的预测标签。
2. 对无标签样本输出置信度和不确定性分数。
3. 当前平台里，主题分类场景更适合使用 CG3 这类“现有类别内最相似”的闭集预测方式；FlexMatch 更适合做主动学习筛选或对比实验。

### 2.4 主动学习采样

1. 先按不确定性从高到低排序。
2. 选择 Top-K 或超过阈值的样本优先给用户标注。
3. 采样策略优先覆盖“模型最不确定”的样本，而不是一味挑最高置信度样本。

### 2.5 人工标注回流

1. 用户对高不确定性样本进行人工标注。
2. 标注结果回写到训练集。
3. 重新训练模型并重新评估所有无标签样本。

### 2.6 高置信度自动接收

1. 当预测置信度高于用户设定阈值时，可自动通过为当前标签。
2. 低于阈值的样本继续保留为待人工复核。
3. 这一步适合做半自动标注，但前提仍然是每类至少已有人工标签。

### 2.7 迭代更新

1. 将新人工标签和自动通过标签一并纳入下一轮训练。
2. 重复“训练 - 采样 - 标注 - 自动接收”的循环。
3. 随着标注量增加，模型准确率通常会逐步提升，不确定性会逐渐下降。

## 3. 推荐策略

1. 主预测器优先用 CG3 风格的闭集分类结果，适合做“最像哪个现有类”的初始判断。
2. 不确定性采样优先保留给人工标注，不建议直接自动落标签。
3. 自动通过只针对高置信度样本开启，并且最好在每个类别都完成最小标注覆盖之后再启用。
4. 如果业务中存在“当前类别集合之外的新类”，需要单独设计拒识或未知类机制，不能只依赖现有分类器。

## 4. 平台中的对应入口

1. smartlabel/apps/data_management/tasks.py 负责根据场景拼装配置并启动算法任务。
2. flexmatch_text.py 负责文本编码、相似度预测和不确定性输出。
3. text_classification/train.py 负责 CG3 基础文本分类流程及 cg3_conf 结果输出。
4. 最终结果通常会输出到 result.csv，供前端展示、人工校验和自动接收使用。

## 5. 输出字段建议

建议结果文件至少包含以下信息：

1. text_id：样本编号。
2. content：文本内容。
3. label：预测或人工标签。
4. confidence：模型置信度。
5. uncertainty_score：主动学习采样分数。
6. uncertainty_stage：不确定性阶段，如 early、mid、late。

## 6. 约束说明

1. 每个类别至少要有一个人工标注样本，否则自动接收风险会很高。
2. 低标注场景下，置信度高不代表一定正确，只代表模型更倾向于某个已知类别。
3. 如果要让系统更适合主动学习，重点不是单纯提高分数，而是让“采样策略”和“人工回流”形成闭环。
